# 电商客服智能体 PRD

文档类型：产品需求文档（PRD）
版本：v1.0
状态：评审中

## 1. 背景

电商客服面临多来源、多轮次、强时效的咨询压力：买家从网页、邮件、小程序同时进来，工单要经历受理、检索知识、分类、答复、转人工、回访等多个环节。传统脚本只能跑固定规则（如关键词分类、固定话术），无法处理“同一位买家追问退换货进度、又顺带问发票”这类跨意图、需要查历史工单的对话；纯聊天机器人则只做一问一答，拿不到订单、工单、知识库和后台动作之间的联动。

因此需要一个 **Agent**：它能在一个会话里自主编排“查工单 -> 检索知识库 -> 决策 -> 更新/处理工单 -> 记录反馈”这一串动作，而不是靠人肉写死每一种分支。这样才可能同时做到：自动应答、跨系统取数、动作落地，并且后续能用人反馈持续优化。

## 2. 用户故事

- 买家小张在小程序里说“我的订单破损了，怎么退款”。Agent 检索到该订单与退换货规则，给出退款方案并创建/更新工单。
- 客服小林打开工作台，看到一张待人工审核的低置信度工单；他点击处理后，Agent 已准备好建议回复和检索到的知识片段，他只需确认或修改。
- 客服主管核查某类投诉激增，Agent 汇总相关工单和知识命中情况，帮助判断是否要新增或修订知识条目。
- 管理员导出偏好数据集与权限审计，用于评估模型回复质量、做 RLHF 闭环。
- 系统在无 API Key 或模型不可用时可自动回退到规则图，保证工单仍能被处理，不阻塞客服。

## 3. 功能清单

### MVP 必须（P0）
- 多角色登录与权限：客户 / 客服 / 客服主管 / 管理员。
- 多来源受理：网页、邮件、小程序创建工单。
- 工单全流程：创建、列表、检索、领取、指派、更新、附件、处理、回访。
- 单 agent 编排：一个会话内自主调用多个工具（查工单、检索知识、更新、处理、反馈）。
- RAG 检索：语义检索 + 重排，命中知识库。
- 角色化工具权限：越权工具对低阶角色不可见。
- 会话记忆与 70% 阈值自动压缩。
- 人工兜底：低置信度自动转人工，无 Key / 失败自动回退经典图。
- 基础指标与监控：/api/metrics、Prometheus、Grafana、Alertmanager。
- 基础评测：幻觉率、召回率、分类准确率脚本。

### 增强版延后（P1）
- 多轮客户自服务对话（完整会话态）。
- RLHF 偏好数据驱动的模型再训练/微调管线。
- 更细粒度的监控面板与告警阈值调优。
- 成本与延迟归因报表。

### 明确不做（不做）
- 不做支付、库存等真实交易系统集成。
- 不做自由形态客服闲聊（不讲产品故事、不闲聊）。
- 不做无人工接入的完全自动驾驶（高风险动作始终留人工入口）。
- 不做通用大模型平台，只覆盖电商客服域。

## 4. 技术架构

- 模型：DeepSeek 系（当前 deepseek-v4-flash），经封装 `chat_text` / `get_llm` 统一出参。
- 编排：LangGraph 单 Agent（`tool_agent.py`），条件边在“模型决定工具”与“收尾”间循环；失败回退到 `agent_graph` 经典规则图。
- 工具：MCP 服务封装工单 CRUD、语义检索、知识库、反馈、通知等 23 个工具；按角色权限表（`TOOL_TIERS`）绑定。
- RAG：向量库（Chroma）+ 启发式重排 `rerank_backend=heuristic`。
- 记忆：LangChain 消息 + 记忆压缩（`_compact`，token 用量超 70% 时滚动摘要，保留最近 6 轮）。
- 服务接口：FastAPI 路由（auth / tickets / agent / channels / rlhf / notifications / stats / metrics / eval）。
- 数据：SQLite 工单库 + 附件目录 + Chroma 向量库，Docker 命名卷持久化。
- 前端：Vue 3 + Element Plus + Vite + Pinia + Vue Router。
- 小程序：原生小程序客户端起单入口。
- 观测：Prometheus 指标 + Grafana 仪表盘 + Alertmanager 告警 + json-file 日志轮转。

## 5. 评测指标

| 指标 | 目标 | 说明 |
|------|------|------|
| 幻觉率 | <= 5% | 检索证据 + LLM 复核（当前 0%，13 条） |
| 检索召回率 recall@3 | >= 95% | 当前 100%（13 条） |
| 分类准确率 | >= 90% | 当前 93.75%（16 条，平均置信度 88.75%） |
| 自动解决率 | >= 60% | 当前 100%（M5 集 6/6） |
| 平均首次响应时间 | <= 30s | 当前 20.7s |
| 人工转接率 | <= 40% | 当前 20% |
| 工单解决时间 | <= 4h | 当前 1.83h |
| 回复采纳率 | >= 75% | 当前 93.3%（RLHF 标注） |
| 成本 | 单次会话可量化为 token 成本 | 计入 /api/stats/launch 口径 |

## 6. 里程碑

- M1：多来源工单受理 + 多角色权限 + 客服工作台。
- M2：RAG 语义检索 + 知识库 + 经典规则图处理流程。
- M3：单 Agent 接入主流程 + 工具权限审计。
- M4：多轮对话与记忆、RLHF 闭环。
- M5：上线评估指标、监控告警、评测脚本、上线评估报告，达到验收基线。

当前状态：M3/M4/M5 核心能力已完成并验证。M3 单 Agent 编排与工具权限审计、M4 多轮对话与记忆 + RLHF 闭环、M5 上线指标与监控告警均已落地，单元测试 13 项通过，真实模型多轮会话与 RLHF 闭环（采纳率 93.3%）已验证。

## 7. 风险登记

| 风险 | 影响 | 缓解 |
|------|------|------|
| LLM 不可用 / 无 Key | 工单处理中断 | 失败自动回退经典规则图；熔断降级 |
| 幻觉 / 证据误导 | 错误答复损害信任 | RAG 带证据 + 幻觉率评测门禁 + 低置信度转人工 |
| 越权调用危险工具 | 删知识、导数据被滥用 | TOOL_TIERS 角色权限 + 审计接口 + 主管可见 |
| 长会话上下文膨胀 | 成本上升、质量下降 | 70% 阈值自动压缩记忆 |
| 成本失控 | 规模化后费用高 | 单会话 token 计量 + 延迟/成本监控 |
| 真实流量指标失真 | 上线评估偏差 | 回填口径记录 + 72h 稳定性观察 + 人工评测集校准 |

## 自评清单

1. 是否有真实约束？是：无 Key 回退、成本/延迟告警、Docker 部署、风控边界均来自实现约束。
2. 是否有明确边界（不做什么）？是：不做交易集成、不做闲聊、不做全自动。
3. 是否有可演示流程？是：客户起单 -> Agent 检索/处理 -> 转人工 -> 主管审计 -> 看板指标。
4. 是否有可评测指标？是：第 5 节 9 项量化指标均有基线。
5. 是否有失败案例？是：无 Key 回退、幻觉转人工、越权禁调均是可复现失败路径。
6. 是否有人能复用/复盘？是：评测脚本、权限审计、回退路径与监控配置可被同行复现复盘。
7. 能否在简历一句话讲清？是：多角色电商客服 Agent，用 LangGraph 单 Agent 编排工单/检索/反馈工具，幻觉率 0%、自动解决率 100%，人工介入率 20%，并含 RLHF 闭环与故障降级。
